# IDEA-003：固定输出字母表与动态内部语言单位

> 类型：隔离架构设计
> 来源：Houming818 与 Trinity 对话整理
> 日期：2026-09-30
> 状态：未验证；等待独立 ARA Claim 与实验合同

## 设计动机

冻结词表时，多元组只能改变已有 token 之间的条件概率。如果一个复合单位不在概率空间中，它就没有独立 ID、概率行、TreeHeap 路径和节点质量，模型不能声称已经形成该复合概念。

因此必须区分：

1. 用于最终输出文本的基础符号；
2. TreeHeap 内部允许持续注册的语言单位；
3. 描述这些单位统计环境的 context 坐标；
4. 由上述对象与树上聚合状态构成的背景场。

## 集合定义

### 基础输出字母表

`Sigma` 是 tokenizer 产生并由 decoder 最终输出的基础 token 集，可以在一个实验版本内保持固定：

```text
Sigma = {x_1, x_2, ..., x_k}
```

### 动态内部语言单位集

`U_t` 是时刻 `t` 已注册到 TreeHeap 的内部语言单位。单位可以是基础 token、复合词或短语：

```text
U_t = {u_1, u_2, ..., u_m}
g = (x_1, ..., x_n) in Sigma*
U_(t+1) = U_t union {g}
```

多元组的一次出现只是训练事件。只有通过准入门禁并执行注册后，`g` 才成为拥有独立统计与路径的语言单位。

### Context 坐标集

`C_t` 是用于记录条件统计的 context 坐标。最初可以只含基础 token，后续是否允许内部复合单位进入 `C_t`，必须由独立实验决定：

```text
p_u(c) = P(c | u),  u in U_t, c in C_t
```

### 背景场

背景场不是词表别名，也不是一个固定大向量。它是语言单位、先验、条件概率行、TreeHeap 拓扑及节点聚合状态组成的版本化统计系统：

```text
B_t = (Sigma, U_t, C_t, P(u), p_u, G_t, p_v, delta_v)
```

## 新单位安装流程

1. 从语料中发现候选多元组 `g`；
2. 计算频率、条件预测增益、跨切片稳定性和复杂度代价；
3. 通过门禁后，为 `g` 分配稳定内部 ID；
4. 建立先验 `P(g)` 与条件概率行 `p_g(c)`；
5. 使用已有背景场给出下坠先验，并为 `g` 分配 TreeHeap route；
6. 只更新该 route 上的节点质量、prototype 与 residual；
7. 若局部容量门失败，再执行 leaf 分裂或拓扑扩容；
8. READ 可以预测内部单位 `g`，随后通过确定性展开返回基础输出序列。

内部单位到输出字母表的展开定义为：

```text
spell: U_t -> Sigma*
spell("葡萄干") = ["葡萄", "干"]
```

因此，动态内部词表不要求立即修改基础 tokenizer 或 decoder 的最终输出字母表。

## 三种不同变化

### 固定单位集上的背景参数更新

`U_t` 不变，只更新已有 `P(u)`、`P(c|u)` 和树上聚合统计。它不能产生新的复合语言单位。

### 内部语言单位扩容

`U_(t+1) = U_t union {g}`，为新单位增加独立统计行、路径和展开规则。这才构成复合概念候选的安装。

### TreeHeap 拓扑扩容

`G_t -> G_(t+1)`，通过 leaf 分裂、增加深度或重构局部子树增加结构容量。内部单位扩容不要求整棵树立即加深。

## 对历史实验的解释修正

冻结词表的双元组、三元组下坠实验只能检验：

```text
多元上下文是否改善已有 token 的条件预测
```

它们不能检验：

```text
TreeHeap 是否形成新的复合语言单位
```

因此，固定词表实验中的统计变化应称为“背景参数更新”，不得称为“背景场扩容”或“新概念形成”。

## 必须建立的后续 Claim

后续实验至少需要分别验证：

1. 注册单位 `g` 是否在封存数据上提供超过其 child 组合基线的条件预测增益；
2. `g` 的 READ 是否依赖其独立概率行和 TreeHeap route；
3. 删除或置乱 `g` 的注册状态是否造成可测退化；
4. `spell(g)` 是否能稳定还原基础 token 序列；
5. 新单位安装后，旧单位的预测质量是否保持在注册容差内；
6. 收益是否超过简单 n-gram 表、哈希表和参数匹配的 flat baseline。

## 当前不主张

- 不主张任何频繁多元组都应注册；
- 不主张内部单位必须成为 tokenizer token；
- 不主张动态词表已经实现；
- 不主张背景场扩容必然产生语义；
- 不主张 TreeHeap 已解决开放词表生成；
- 不用历史冻结词表实验为本设计提供成功证据。
