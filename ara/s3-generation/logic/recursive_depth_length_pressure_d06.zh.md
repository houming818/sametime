# D06：递归深度与句长压缩板

日期：2026-08-28

Claim：`S3-RECURSIVE-DEPTH-LENGTH-PRESSURE-D06`

状态：`preregistered`

## 1. 起点

D05 证明当前冻结 Decoder 不会把较浅 READ 自动解释成较短句子。depth 5 反而经常
无法生成 EOS，进入高频循环。D06 不再等待该关系自行出现，而是在架构中加入一个
“压缩板”：递归深度决定本层可用生成容量，容量使用率只向 EOS 提供单调残差压力。

本阶段先验证深度与句长可以稳定耦合，不训练“应该保留什么内容”。语义压缩学习属于
压缩板成立后的下一阶段。

## 2. 层级容量

推理时不能读取目标句长度，因此每条输入使用源句有效 token 数 `Lx` 计算容量。去除
方向 token 与 EOS 后，完整深度 `D=7` 的容量为 `Lx`：

```text
B7 = max(2, ceil(Lx))
B6 = max(2, ceil(Lx / 2))
B5 = max(2, ceil(Lx / 4))
```

一般形式：

```text
Bd = max(Bmin, ceil(Lx * 2^(d-D)))
```

`Bd` 是可用内容地址上限，不是人工缩句标签。所有深度仍使用相同的全局
`max_output=128`；每条样本自己的压缩板容量由结构公式计算。

## 3. 可微 EOS 压力

设第 `t` 步的容量使用率为：

```text
r(t,d) = (t + 1) / Bd
```

压力门为：

```text
g(t,d) = sigmoid(k * (r(t,d) - tau))
```

本实验固定 `k=20`、`tau=0.85`。对原始词表概率 `P`，只做如下混合：

```text
P'(v)   = (1-g) * P(v),             v != EOS
P'(EOS) = (1-g) * P(EOS) + g
```

因此所有非 EOS token 的相对排序保持不变。压力只增加 EOS 的概率，并且随容量使用率
单调增加。若到达 `Bd` 后仍未停止，硬边界强制 EOS，作为防循环安全措施。硬边界不用于
声称模型已经学会停止；实验会单独报告硬边界触发率。

## 4. 实验设计

冻结 D05 相同的三个 READ checkpoint：seed `10101/10102/10103`。使用相同的 128 条
WMT test rows。每条输入、每个深度运行：

- greedy 1 次；
- temperature `0.8`、top-p `0.9` 采样 8 次；
- depth `5/6/7`；
- 记录预算、实际长度、EOS 是否在硬边界前出现、重复率、BLEU 与固定样例。

D05 的无压力结果作为冻结基线，不重新训练参数。

## 5. Predict

### P0：实现合同

- 生成不读取 target，不做 teacher forcing；
- 三深度共享模型参数与全局 `max_output`；
- `B5 <= B6 <= B7`，非 EOS 概率的两两比值在压力前后保持不变；
- 证据、checkpoint 和 test-row 哈希完整。

### P1：深度-长度耦合

每个 seed 的采样中位长度满足：

```text
median(L5) < median(L6) < median(L7)
```

并且至少 `80%` 的同句、同采样编号满足 `L5 <= L6 <= L7`。至少两个 seed 通过。

### P2：近似二倍容量响应

至少两个 seed 满足：

```text
0.15 <= median(L5/L7) <= 0.40
0.35 <= median(L6/L7) <= 0.70
```

### P3：软压力有效

各深度至少 `65%` 的采样在硬边界之前自然选择 EOS；所有深度非空率不低于 `95%`。
否则只能证明硬截断有效，不能证明 EOS 残差压力有效。

### P4：完整深度安全性

相对 D05 无压力 depth 7：

- BLEU4 下降不超过 `1.0`；
- 相邻重复率增加不超过 `0.05`。

### P5：跨 seed 复现

至少两个 seed 通过 P1、P2、P3，且没有 seed 出现稳定反向长度关系。

## 6. 结论边界

D06 即使全部通过，也只说明压缩板能把递归深度变成稳定的句长约束，并保持基本生成
行为。它不是“模型已经学会缩句”的证据。下一阶段才会让压缩状态通过 UNFOLD 重建
完整目标，使梯度在有限容量中学习保留哪些信息。
