# TreeHeap 能力阶梯：参考 GPT-2 / GPT-3 的研发路线

状态：研究路线，不是 Claim，不产生 `supported` 结论。

记录日期：2026-08-28

作者：Houming818 & Codex Review

## 1. 为什么记录这条路线

TreeHeap 的长期目标包括私有协议、通用生成、知识关联和世界模型。但是这些目标不能由
一次实验同时承担。若在输入协议仍然很弱时直接用因果推理或世界模型题目验收，任何负
结果都无法区分以下原因：

```text
输入没有进入模型
协议容量不足
Decoder 没有读懂协议
训练数据没有包含该知识
模型会语言关联，但不会组合关系
模型确实缺少世界状态建模能力
```

GPT-2 和 GPT-3 的研发过程提供了一个更合适的历史参照：先用统一语言目标观察能力随
规模连续出现，再把零样本、单样本和少样本能力分级测试；不要求早期模型一步完成最终
任务。

本路线只借鉴这种**分级研究方法**。它不把 Transformer 参数量、训练预算或产品指标
直接搬到 TreeHeap，也不把 TreeHeap 描述成 GPT 的替代品。

## 2. GPT-2 阶段真正证明了什么

GPT-2 同时训练了约 `117M / 345M / 762M / 1.5B` 四档模型。论文观察到：

1. 跨域语言建模随容量稳定改善；
2. 连贯段落生成明显增强；
3. 问答、摘要和翻译等未专门训练的任务开始出现零样本行为；
4. 很多任务仍然只比简单基线稍好，论文明确称其实用能力很初步；
5. 所有规模仍然欠拟合 WebText，继续训练仍能改善 held-out perplexity。

翻译结果尤其适合校准我们的预期。GPT-2 在几乎没有法语训练数据、只用上下文示例唤起
任务的条件下，WMT-14 英译法约为 `5 BLEU`，法译英约为 `11.5 BLEU`。这个结果证明
“统一语言模型中开始出现翻译能力”，并不代表翻译产品已经完成。

因此 GPT-2 阶段的核心结论不是世界模型，而是：

```text
统一语言目标 + 多样语料 + 容量增长
    -> 多种任务行为开始从同一参数系统中出现
```

## 3. GPT-3 阶段增加了什么

GPT-3 延续自回归语言建模，并系统训练从 `125M` 到 `175B` 的多个规模。它把任务适应
分成三种前向测试：

```text
zero-shot：只有任务说明
one-shot：任务说明加一个例子
few-shot：任务说明加少量例子
```

测试时不更新梯度。论文报告多数任务在三种设置下随规模相对平滑地改善，而且模型越大，
few-shot 相对 zero-shot 的收益往往越明显。与此同时，自然语言推断和部分阅读理解仍然
困难。

这给 TreeHeap 两个直接启示：

1. 语言损失曲线与能力曲线要分开观察；
2. “看到几个例子后改变任务行为”应当是较后阶段的验收，不是输入协议刚出现时的门槛。

## 4. TreeHeap 当前坐标

截至 D07R2，当前证据应按下表解释：

| 能力 | 当前状态 | 证据边界 |
|---|---|---|
| 目标语言统计规律 | 已有证据 | source 清零后仍能依靠参数与 teacher-forced 目标前缀降低 NLL |
| 专门训练的真实翻译 | 已有数值证据 | 历史 TreeHeap 配方 token-BLEU4 约 `9.9--12.7`，但不是统一 SacreBLEU |
| 输入身份进入协议 | 弱正证据 | D07R2 的 shuffle 损失约 `+0.096--+0.142` NLL |
| 协议总体帮助 Decoder | 弱正、未过门 | D07R2 的 zero 损失只有 `+0.036--+0.071`，低于预注册 `+0.10` |
| 冻结 checkpoint 的多任务萌芽 | 未测试 | 不能由专门 WMT 训练成绩推出 |
| few-shot 上下文学习 | 未测试 | 不能由 teacher forcing NLL 推出 |
| 可查询世界模型 | 未证明 | 暂不作为最近一级验收 |

历史约 `10` 的 TreeHeap token-BLEU4 与 GPT-2 的 WMT BLEU 不是同一指标，也不是同一
训练条件。它可以证明 TreeHeap 已经存在真实 seq2seq 任务通道，不能证明整体能力超过
GPT-2。正式横向比较必须统一数据、测试集、tokenizer、SacreBLEU signature、训练算力
和是否使用平行监督。

## 5. 能力阶梯

后续不再用单独的 `Cxx` 作为对外可读名称。每一级先使用能力名称，实验编号只作为内部
追踪字段。

### 阶梯一：语言底座

目标：模型能从语料学习词频、句式、局部和长程续写规律。

主要测试：

```text
held-out NLL / PPL
自由生成重复率
固定 dreams 的连贯性
不同上下文下的下一个 token 分布差异
```

当前判断：已有基础证据，但生成质量不稳定。该阶梯不是产品完成。

### 阶梯二：输入协议

目标：当前输入经过 TreeHeap 后，稳定、因果性地改善当前输出。

核心门：

```text
NLL(native) < NLL(shuffle)
NLL(native) < NLL(zero)
```

两种差值必须在预注册的深度数和多 seed 上超过门槛。还必须测量协议槽位的路径覆盖率、
槽位间重叠率和新增容量的边际收益，避免多个 query 重复读取同一小片 subheap。

当前判断：D07R2 只得到一致的弱正符号，尚未完成本阶梯。

### 阶梯三：任务萌芽

目标：在同一个广谱预训练 checkpoint 冻结后，不做任务梯度更新，观察不同任务行为是否
开始出现。

候选测试：

| 任务 | 第一门槛 |
|---|---|
| 中文续写 | 优于 unigram、复读和 target-only 基线 |
| 完形填空 | 能利用局部与长程上下文 |
| 翻译提示 | 超过逐词替换和原文复读基线 |
| 文内问答 | 超过按问题类型返回最高频答案的基线 |
| 摘要提示 | 输出与全文相关，且优于随机句抽取 |

这一阶梯模仿的是 GPT-2 的“任务开始出现”，不要求商业可用，也不要求每项任务都达到
强监督模型水平。

### 阶梯四：TreeHeap Scaling Curve

目标：判断能力是随参数、数据和算力增长，还是只在某个偶然配方中出现。

最低实验矩阵使用相对规模，避免过早绑定绝对参数量：

```text
参数规模：1x / 2x / 4x
训练 token：1x / 2x / 4x
至少保留一个固定算力比较面
```

每次同时报告：

```text
Test NLL / PPL
标准 SacreBLEU 或任务指标
native-zero / native-shuffle
重复率与生成长度
参数量、训练 token、GPU 小时和估算 FLOPs
固定 dreams
```

需要观察两条曲线：普通语言能力是否改善，TreeHeap 的结构因果贡献是否也改善。如果
NLL 持续下降而结构贡献趋近于零，则模型可能在强化语言骨架而绕过 TreeHeap 协议。

在长训练前，应使用早期曲线预测后续收益，并设置停止门。该方法借鉴 scaling-law 研究，
但必须用 TreeHeap 自己的数据拟合，不能直接套用 Transformer 的指数。

### 阶梯五：上下文适应

目标：冻结 checkpoint，仅改变输入上下文，测试 zero-shot、one-shot、few-shot。

最小例子：

```text
苹果 -> 水果
阿莫西林 -> 药品
土豆 -> ?
```

验收不是一次答对，而是 few-shot 相对 zero-shot 在多种任务、多 seed 和改写模板下产生
稳定增益，同时结构干预证明这些示例经过 TreeHeap H_state 参与了预测。

### 阶梯六：知识关联

目标：同一事实换一种表述后仍能检索关联，不要求多步因果。

```text
训练或上下文：西西弗斯推着石头上山。
测试：谁在推石头？
测试：石头由谁推动？
```

这一阶梯先区分“保存原句”“目标词频关联”和“跨表述关系提取”，再讨论长期记忆系统。

### 阶梯七：世界状态与推理

目标：对象、关系和状态可以组合、更新并参与预测。

候选测试包括状态转移、数量变化、时序、简单因果和反事实。只有前六级得到可重复证据后，
世界模型才成为正式 Claim；在此之前它只是长期方向。

## 6. 最近航线

当前只推进“输入协议”阶梯：

```text
1. 预注册结构 ownership / subheap coverage 候选；
2. 对比自由 query、结构分区和随机分区；
3. 直接测量 slot 路径覆盖率与重叠率；
4. 重做 native / shuffle / zero 因果门；
5. smoke 过门后才进入多 seed 和长训练；
6. 输入协议稳定后，建立广谱预训练 checkpoint 和任务萌芽测试。
```

禁止用追加 steps 掩盖结构门失败，也禁止用某个专门任务的 BLEU 直接升级“通用能力”或
“世界模型”状态。
