# S3 多分辨率语言课程 T0：教师合成候选

状态：预注册，尚未形成语言能力结论。

日期：2026-10-12

## 问题

TreeHeap 的树深度提供了多个计算尺度，但深度本身不会自动获得“核心概念、
极短句、缩句、完整句”的语言含义。如果训练只在完整目标句上计算损失，多个
不同的中间表示都可能得到相同的最终 NLL，中间尺度的语义因此不可辨识。

本试验不训练 TreeHeap。它先验证能否用 io 上冻结的本地 Qwen3-8B，从已发布
的高置信中英平行语料中产生一批可审计的、同义但信息量逐级增加的中文目标
候选，为后续多尺度监督提供物料。

## 数据合同

- 输入：`NioClean-ZHEN-S098-7M-v2/pairs.tsv`。
- 固定 seed：`20261012`。
- 只选择长度适中的中文完整句；选择过程使用确定性 reservoir sampling。
- 每条记录保留原始行号、英文源句、中文完整译文以及输入文件 SHA-256。
- 教师输出永远标注为 `teacher_synthetic`，不能称为人工真值。

## 四级目标

对于英文源句 `x` 和中文完整译文 `y3`，教师只生成下面三级；`y3` 直接来自
已发布语料，不要求教师复写：

1. `y0/core`：核心词组，只保留主体、动作和关键对象；
2. `y1/short`：极短句，能够独立表达中心事件；
3. `y2/reduced`：语法完整的缩句，保留主要事实、否定和关键数量；
4. `y3/full`：原始中文完整译文。

长度必须满足：

\[
0 < |y_0| \le |y_1| \le |y_2| < |y_3|.
\]

长度有序只证明形式上的分辨率，不证明语义保真。

## T0 Claim

`S3-MULTIRES-CURRICULUM-T0-C01`：在固定输入、固定 seed、冻结本地教师和贪心
解码条件下，教师能够生成机器可解析且长度有序的四级中文候选，smoke 中 JSON
解析率至少 95%，长度有序率至少 85%，综合接受率至少 80%。

通过 C01 只允许把正式批次作为“候选训练物料”保存。它不证明：

- 各尺度语义完全等价；
- 更短目标是唯一正确的缩句；
- TreeHeap 能学习或利用这些尺度；
- 教师生成优于人工摘要或规则抽取；
- 多尺度训练会改善最终生成。

## 执行阶梯

1. 单元测试：只测试解析、长度门和确定性抽样，不加载模型；
2. smoke：24 条；
3. 仅当 smoke 三个形式门全部通过时，释放 512 条正式候选；
4. 保存全部原始教师输出、拒绝原因、接受集、summary 和 SHA-256；
5. 后续另立 Claim，用人工抽样或独立评价检验语义保真，再决定是否进入训练。

## 停止条件

仅在 OOM、CUDA/NVIDIA Xid、NaN/Inf、模型或输入身份损坏、JSON/evidence 无法
写入、270W 功率限制解除时停止。单个样本不合格只进入拒绝集，不中断整批。

## T0 smoke 结果与 R1 预注册

任务 655 完成了 24 条 smoke 后被门禁阻止。JSON 解析率为 `1.0`，长度有序率
为 `0.8333`，综合接受率为 `0.5`。主要拒绝原因为 `core` 上限过紧，以及
`short` 与 `reduced` 没有形成信息差。该结果拒绝原 C01，不释放正式批次。

检查原始输出后，R1 不降低“不同尺度必须有信息差”的要求，而是修正提示合同：

- 原合同只给每层最大长度，教师容易把三层都压到最短；
- R1 为 `short` 和 `reduced` 同时给出下限与上限；
- R1 明确要求每个更细尺度至少增加一项事实；
- `core` 上限由完整句的约 20% 放宽到约 30%，避免专名和数量天然超限。

R1 使用与 T0 相同的 24 条输入和 seed。门禁保持不变：解析率至少 95%，严格
长度有序率至少 85%，综合接受率至少 80%。对应 Claim 为
`S3-MULTIRES-CURRICULUM-T0-R1-C01`。这是一项由失败 smoke 启发后重新预注册的
合同，不得回写成 T0 原始预测。

R1 的解析率为 `1.0`、严格长度有序率为 `0.9583`，但综合接受率只有
`0.1667`。16/24 的主要拒绝原因是 `reduced` 短于人为规定的完整句 40%。原始
样例表明，其中多条仍是语法完整且信息逐级增加的有效缩句。该下限测量的是
压缩比例，不是语义保真，因此不能作为候选语料的真值门。

R2 据此重新预注册：字符区间继续作为提示和观测，不再决定接受；接受门只要求
JSON 完整且 `core < short < reduced < full`。另外增加中文字符占比门，避免已
发布高置信集合中少量英文混入行进入本试验。R2 仍维持解析率 95%、严格长度
有序率 85%、综合接受率 80% 的门禁，对应 Claim
`S3-MULTIRES-CURRICULUM-T0-R2-C01`。语义保真仍留给独立人工或异源评价，不能
从长度顺序推出。

R2 接受 14/24。运行后审计发现 summary 的 `monotonic` 计数错误地使用了
`core <= short <= reduced`，而 Claim 和接受器要求严格 `<`；因此 summary 中
`0.9583` 的长度有序率无效，R2 拒绝且不得用于正式释放。

R3 不再要求一次提示同时构造三个尺度，而使用与压缩方向一致的教师链：

\[
y_{full}\rightarrow y_{reduced}\rightarrow y_{short}\rightarrow y_{core}.
\]

每次调用只压缩直接上一级，并保留该级原始输出。这样每个尺度都有明确父状态，
也避免教师在一个 JSON 中写出三个等长的同义改写。严格长度计数器同步修复为
`<`。R3 使用 Claim `S3-MULTIRES-CURRICULUM-T0-R3-C01`，其门禁不变；这是最后
一轮物料协议 smoke，若仍失败则停止自动调整，保留结果等待人工重新设计。

## R3 正式结果

任务 658 已完成。R3 smoke 为 24/24 接受，随后按门禁释放 512 条正式批次。
正式结果为：

- JSON 解析：512/512；
- 严格满足 `core < short < reduced < full`：488/512（95.3125%）；
- 接受：488/512（95.3125%）；
- 拒绝：24 条，其中全部存在非严格长度顺序，4 条同时出现 `short` 与
  `reduced` 重复；
- 接受集中，相对完整句的平均长度比例依次为：`core=0.1409`、
  `short=0.2241`、`reduced=0.4077`；
- 输入 SHA-256 为
  `299134867398720cc6d407eadd6de4fb237812319d113fbe12071758e79d92c8`；
- 教师配置 SHA-256 为
  `f7c4eadfbbf522470667b797a3c89be2524832d2d599797248dc304fff447c30`；
- 3090 运行前后均保持 270W 功率限制；峰值分配显存约 16.52GB；
- 根目录 `SHA256SUMS` 全部校验通过。

因此 `S3-MULTIRES-CURRICULUM-T0-R3-C01` 在其形式合同内得到支持：冻结本地
教师可以通过逐级压缩链稳定地产生可解析、长度严格有序的候选物料。该 Claim
只支持候选物料生产协议，不支持语义保真、人工质量或下游 TreeHeap 收益。

正式训练继续保持关闭。下一步若推进，应先从 488 条接受集中做独立语义审计，
检查主体、否定、数量、因果和关键对象是否在各尺度中得到保留，再另立训练 Claim。
