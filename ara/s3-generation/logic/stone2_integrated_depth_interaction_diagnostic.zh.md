# STONE-2 C03-D01：多深度 READ 组合消融诊断

## 状态

- 类型：冻结 checkpoint 的诊断实验，不新增训练、不修改参数。
- 前置结果：C03 smoke 的 9 个门中有 8 个通过；`S7_multilevel_positive` 未通过。
- 目的：解释“全部非叶层一起读取有收益，但删除任意单层反而略有改善”的非加性现象。

## 观察

C03 smoke 在同一测试集上得到：

- 关闭全部多深度 READ：Test NLL 增加约 `0.1311`；
- 单独删除有效深度 0 到 7 中任意一层：Test NLL 反而下降约 `0.0027` 到 `0.0043`；
- 深度 8 不存在于实际 `H_state`，旧审计按 `heap_width` 多检查了一层，结果自然为零。

因此，不能把“全开相对全关更好”直接解释为每层都独立承载了有效协议。可能性至少有三种：

1. 多层信息存在协同，必须成组出现；
2. 每层带来很小的共同收益，同时也带来更大的局部噪声；
3. `leaf_only` 与 native 的模式差异制造了假象。

## 冻结设计

以 `task/PT/checkpoint_best.pt` 为唯一模型，保持测试行、batch、tokenizer 和全部参数不变。实际 8 个深度分为：

- coarse：0、1、2；
- middle：3、4、5；
- fine：6、7。

枚举三个组的全部 8 种启用组合。每次只控制哪些深度允许执行同一个共享 `READ kernel`，其余计算完全相同。

## 预注册解释规则

令价值函数为：

`V(S) = NLL(none) - NLL(S)`

其中 `S` 是启用的深度组。`V(S) > 0` 表示该组合优于完全关闭多层 READ。

记录：

1. 三组 Shapley 值，其总和必须等于 `V(all)`；
2. 两两与三组交互项；
3. full、none、各单组、各双组的 NLL；
4. 重复执行 native 与 none，检查评估确定性。

判读：

- 若至少两个组的 Shapley 值为正，且 `V(all) > 0`，则记录“组合协议候选”；这仍不能补签原 S7。
- 若收益几乎全部来自一个组，则下一步只围绕该分辨率定位。
- 若 Shapley 多数为负，或重复评估不一致，则停止正式长训，先修 READ 能量或审计实现。

无论结果如何，本诊断都不得事后修改 C03 的失败结论，也不得自动启动正式预训练。

## 结果（2026-08-23）

任务 `293` 在冻结 PT checkpoint 上完成了 256 行、8 种组合的确定性评估。

| 启用组 | Test NLL | 相对 none 的收益 |
|---|---:|---:|
| none | 8.2273 | 0 |
| coarse | 8.1307 | 0.0966 |
| middle | 8.1312 | 0.0962 |
| fine | 8.1785 | 0.0488 |
| coarse + middle | 8.0924 | 0.1349 |
| coarse + fine | 8.1067 | 0.1206 |
| middle + fine | 8.1073 | 0.1200 |
| all | 8.0962 | 0.1311 |

Shapley 贡献为：coarse `0.0543`、middle `0.0538`、fine `0.0229`，三者
之和严格等于 full 相对 none 的 `0.1311`。重复评估差为零。

这支持“多个分辨率组都携带可用信息”，但不支持“组间协同增益”：三项两两
交互均为负，分别约 `-0.0579`、`-0.0249`、`-0.0250`。更准确的解释是：
**多分辨率贡献是分布式的，同时共享 READ kernel 在不同深度间产生了冗余和轻微
干扰。** 原 C03 的 S7 仍保持失败；后续应注册新的能量归一化或深度交互实验，
而不是补签通过。
