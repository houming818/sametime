# 等容量硬协议实验报告

## 结论

在当前真实 WMT 英文侧 token-context 任务上，互斥性与空间关系可以在
没有 NCE、没有随机 token embedding 的条件下共同形成；但训练协议
必须与最终读出协议一致。若训练时允许多 leaf 混合、部署时改成单
leaf，软 NLL 会掩盖硬读出的失败。将严格等容量单 leaf 指派放入前向
计算后，这个问题被修复，并在 256、512、1024 token 三档复现。

## 关键实验链

1. 任务 476--478：确定性等容量树在 256--1024 token 上保持每 leaf
   恰好 4 个 token，并在 held-out NLL 与近邻路径上优于随机/频率控制。
2. 任务 483：可微软 Sinkhorn 训练成功，但软/硬 held-out NLL
   `4.78887/5.61469`，证明软混合不是可用的单 leaf 协议。
3. 任务 484--491：常量熵压力从 `0` 扩展到 `64`，始终未形成离散
   路由；去掉容量的控制发生严重拥挤，最多 `189/256` token 进入同一
   leaf。
4. 任务 492--493：前向采用严格等容量 one-hot，反向使用 soft
   Sinkhorn 直通梯度。相同初始化下，软前向与硬协议最终硬 NLL
   `5.51873/4.77457`，硬协议通过全部门。
5. 任务 494--495：硬协议在 512、1024 token 上继续通过。

## 规模结果

| Targets / contexts | 语料行数 | 训练 NLL 降幅 | 最终硬 NLL | 冻结树 | 随机树 | 近邻 LCP | leaf 容量 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 256 / 512 | 100K | 0.05563 | 4.77457 | 4.77779 | 4.85159 | 2.30339 | 4..4 |
| 512 / 1024 | 200K | 0.07070 | 5.25649 | 5.26116 | 5.32978 | 2.48307 | 4..4 |
| 1024 / 2048 | 500K | 0.07902 | 5.70199 | 5.70540 | 5.77995 | 2.82096 | 4..4 |

不同档的 context 词表不同，绝对 NLL 不可跨行直接比较；每行只与同
规模的冻结/随机控制比较。

## 当前支持的机制

- 容量投影提供互斥：每个 leaf 始终恰好容纳 4 个 token。
- 真实 `P(context|token)` 的 Hellinger 距离提供空间吸引。
- 梯度可以更新共享 leaf 条件分布。
- 离散路由必须参与前向任务，不能只在训练结束后临时离散化。

## 尚未证明

这些实验没有证明句子组合、翻译、自由文本生成、当前句条件下的一词
多义，也没有证明新 token 在线加入时旧路径稳定。下一条航线应从
“token-context 空间”进入“句内组合后仍可硬读出”，而不是继续扩大
当前词表数字。
