# 固定容量的 Subheap 旋转

状态：design
Claim：`M0-ROT-C02`
Predict：`P-ROT02`
日期：2026-07-21

## 架构决定

旋转不能生成更大的 TreeHeap。系统启动时拿到容量为 `C` 的固定节点池，
之后所有计算都必须留在这个空间内：

```text
R_(S, phi): H_C -> H_C
```

`S` 是已经存在的 subheap，`phi` 来自预先登记的有限方向集合。`R` 可以
重排 `S` 内部的数据地址，也可以修改内部父子边，但必须满足：

```text
旋转前后节点池相同
旋转前后容量都等于 C
R^-1(R(H)) = H
S 外部的状态完全不变
```

递归过程不能申请另一棵 TreeHeap。实现若需要 scratch buffer，也必须在
系统启动时计入固定内存预算，并在每一步重复使用。

## kernel 如何参与

旋转只是改变观察结构的方向，不是生成更多候选。共享 kernel 在标准方向
工作：

```text
局部结构旋到标准方向
同一个 K_theta 读取并计算局部更新
再把结果旋回原来的树坐标
```

这样，相同的 `theta` 可以在不同地址、不同方向的 subheap 上复用。mirror
只是两个方向的特例；真正的树左旋/右旋也可以修改父子指针，但不能增加节点。

## 如何扩展到整棵树

局部 kernel 在现有树上重复卷积：

```text
H_(t+1) = ApplyAllSubheaps(H_t, K_theta, R, gates)
```

经过 `t` 轮，信息大约能传播 `t` 个结构跳数。增长的是可观察范围，不是
内存。系统具有明确上限：

```text
空间 = O(C)
时间 = O(T_max * C * 局部kernel成本)
```

`C` 和 `T_max` 都是硬限制。达到上限仍然没有答案，就返回 `UNRESOLVED`，
不允许扩容。

## 预测和证伪

计划在固定 127 节点 TreeHeap 上验证：旋转/逆旋转精确；节点数和内存不变；
只在标准方向训练的共享 kernel 能迁移到未见地址和已登记方向；取消旋转对齐
会损害迁移；多轮局部卷积能把信息传播到整树；超过轮次预算会停止。

对照组包括：无旋转共享 kernel、地址专属 kernel、同参数 flat MLP、随机
非结构置换。只要发生动态扩容、逆变换失败、迁移不成立，或者随机置换同样
有效，就否定该 claim。

这个设计不声称旋转本身产生语义知识。它只主张：在固定物理内存中，结构
对称性可能让一个有用的局部规则被更多位置和方向复用。
