## 项目概述
- **项目名称**: SameTime (Study and Tuning for LLMs)
- **项目用途**: 学习 LLM/LLaMA 模型相关技术，包括微调、推理、性能优化
- **技术栈**: Python 3.10+, PyTorch 2.0+, Transformers, PEFT, DeepSpeed, Docker
- **仓库结构**: 
  - `./scripts/` - T1 工程师编写的微调/推理脚本
  - `./data/` - 训练/测试数据集（不包含生产数据）
  - `./models/` - 模型权重存储（gitignored）
  - `./experiments/` - 实验配置和日志
  - `./docs/` - 学习笔记和文档
  - `./benchmark/wmt/` - NMT 历史演进复现代码（Phase 0→6）
  - history.txt 每次重要操作或变更，都主动记录到history.txt中
  - Makefile 快速指令文件，用于快速构建与触发测试文件
- 环境描述：
  - 开发主机 ni 开发账号nio 无显卡
  - 运行主机 io 运行账号houming818 运行主机有24G显存 有限采用DOCKER_HOST的方式基于docker运行
  - 有一个docker的registry: https://reg.grepcode.cn 可以使用,要善于将公网的image，缓存到本地重复使用，例如：
  docker tag nvidia/cuda:12.1.0-runtime-ubuntu22.04 reg.grepcode.cn/sati/nvidia_cuda:12.1.0-runtime-ubuntu22.04

## 环境隔离与测试规范

### 分层镜像缓存策略
将镜像分为两层，避免每次迭代都下载 CUDA wheels（~2.5GB）：
```
base/           # 底层：nvidia/cuda + python3 + torch cu121（频繁变化）
Dockerfile      # 应用层：FROM base + 业务脚本（每次迭代变化）
```
构建一次 base 后 push 到 registry，后续应用层迭代只需秒级构建。

```bash
# 首次构建 base（15-20 分钟）
DOCKER_HOST=ssh://houming818@io.grepcode.cn \
  docker build -t reg.grepcode.cn/sati/sametime-base:cu121-py310 benchmark/hello_sati/base/
DOCKER_HOST=ssh://houming818@io.grepcode.cn docker push reg.grepcode.cn/sati/sametime-base:cu121-py310

# 应用层迭代（秒级）
DOCKER_HOST=ssh://houming818@io.grepcode.cn \
  docker build -t reg.grepcode.cn/sati/sametime-hello:latest benchmark/hello_sati/
DOCKER_HOST=ssh://houming818@io.grepcode.cn \
  docker run --gpus all --rm reg.grepcode.cn/sati/sametime-hello:latest
```

### 历史记录规范
- 每次实验/操作完成后，将操作过程和可复现步骤记录到 `history.txt`
- `history.txt` 按时间倒序排列（最新在前），每条包含日期、目标、工作流、结果
- 脚本代码与日志分离：脚本放 `benchmark/xxx/`，日志放 `history.txt`
