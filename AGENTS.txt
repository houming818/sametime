## 工作纪律

1. **对齐证据，不推测** — 说"5 小时没出 epoch"之前，先确认 `date` + `stat log mtime` + `docker ps uptime`。错了就立刻纠正。
2. **稳定优先** — 不绕过问题、不随意改参、不掩盖硬件故障。
3. **命名统一** — 全部实验遵循 `{架构}.{线性算法}.{损失}-{序号}` 规范。
4. **记录可追溯** — 每一步操作落到 AGENTS.txt 或 history.txt，不依赖记忆。

## 实验命名规范

格式: `{架构}.{Linear算法}.{损失}-{序号}`

### 架构（Layer 1）
| 缩写 | 全称 |
|------|------|
| R | RNN |
| A | Attention (LSTM+Bahdanau) |
| T | Transformer |

### Linear 算法（Layer 2）
| 缩写 | 全称 | 说明 |
|------|------|------|
| STD | Standard | 全量 Linear(d, V) + Softmax（默认） |
| RST | Restricted | Top-k Softmax，k=K_lang×V |
| SPR | Semantic Prefix Routing | 树递归路由判定 |
| HSH | Hash-based | 哈希碰撞桶 |

### 损失（Layer 3）
| 缩写 | 全称 |
|------|------|
| CE | Cross-Entropy |
| SB | CE + SoftBLEU（α=0.5, k=170） |

### 全局实验 ID

每个实验分配唯一 **E-XXX** 作为主键，跨所有系列统一计数：

| 编号范围 | 系列 | 数量 |
|------|------|------|
| E-001 ～ E-008 | R (RNN, IWSLT14) | 8 |
| E-009 ～ E-023 | A (Attention, IWSLT14) | 15 |
| E-024 ～ E-030 | TI (Transformer, IWSLT14) | 7 |
| E-031 ～ E-032 | T→TW (Transformer, WMT14) | 2 |
| **E-033** | **下一个可用** | — |

格式：`{架构}.{线性}.{损失} / E-XXX / {配置}`

示例：`T.STD.CE / E-033 / d256/3L, 30ep`

### 示例

| 实验 | 含义 |
|------|------|
| T.STD.CE-1 | Transformer, 标准 Linear, CE, 实验 1 |
| T.RST.SB-1 | Transformer, Restricted top-k, CE+SoftBLEU |
| A.STD.CE-1 | Attention, 标准线性, CE |
| A.STD.SB-1 | Attention, 标准线性, SoftBLEU |

## 环境隔离与测试规范

### 分层镜像缓存策略
将镜像分为两层，避免每次迭代都下载 CUDA wheels（~2.5GB）：
```
base/           # 底层：nvidia/cuda + python3 + torch cu121（频繁变化）
Dockerfile      # 应用层：FROM base + 业务脚本（每次迭代变化）
```
构建一次 base 后 push 到 registry，后续应用层迭代只需秒级构建。

```bash
# 首次构建 base（15-20 分钟）
DOCKER_HOST=ssh://houming818@io.grepcode.cn \
  docker build -t reg.grepcode.cn/sati/sametime-base:cu121-py310 benchmark/hello_sati/base/
DOCKER_HOST=ssh://houming818@io.grepcode.cn docker push reg.grepcode.cn/sati/sametime-base:cu121-py310

# 应用层迭代（秒级）
DOCKER_HOST=ssh://houming818@io.grepcode.cn \
  docker build -t reg.grepcode.cn/sati/sametime-hello:latest benchmark/hello_sati/
DOCKER_HOST=ssh://houming818@io.grepcode.cn \
  docker run --gpus all --rm reg.grepcode.cn/sati/sametime-hello:latest
```

## 实验纪律 (2026-05-07 复盘确定的规则)

1. **每轮实验必须复盘** — 跑完不总结 = 白跑。记录在 history.txt。
2. **控制变量** — 一次只改一个参数。B6/B7 改了 k_lang + 架构 + max_n 三个变量。
3. **失败比成功更有价值** — B8 的 0.74 BLEU 比 B3 的 11.70 教了更多东西 (dropout 过杀)。
4. **GPU 时间是有限的** — 33h 产出 11.70 BLEU, 还需要精打细算。
5. **每次操作记 FamilyChat.txt** — 给别人看, 也给自己看。

### 已知硬件问题

1. **XID 79 — GPU has fallen off the bus**
   - 根因: B85M-D3H 的 PCIe 控制器（2013）与 RTX 3090（2020）电源状态转换不兼容
   - 现象: 训练约 1 小时后 GPU 从 PCI 总线断开，`lspci -d 10de:` 显示 `rev ff`
   - 已部署缓解: `nvidia-smi -pl 250`(功率墙) + `pcie_aspm=off`(内核参数) + nvidia-power-limit.service(systemd)
   - 根治: 需要换主板+CPU 平台（B550+Ryzen 或 B760+Intel 12代+），支持 Above 4G Decoding / Resizable BAR
   - IaC 位置: `engines/sedcode-script/ansibles/roles/l1_os_security/tasks/dirty_frag.yml`

2. **Dirty Frag (2026-05-07)**: 通用 Linux LPE，通过 esp4/esp6/rxrpc 解密路径提权
   - 已部署: `/etc/modprobe.d/dirtyfrag.conf` 黑名单
   - 无 CVE 无补丁，缓解措施已生效

3. **Copy Fail (CVE-2026-31431)**: 已修复，全集群 kernel 升级完成

### 训练经验教训

- **batch_size 与 VRAM**: d256/3L + WMT14: batch=256 → OOM, batch=128 → 15GB VRAM 正常
- **真实 epoch 时间**: WMT14 4.5M 句, d256/3L, batch=128 → ~30 分钟/epoch (包含验证 greedy decode)
- **分词缓存**: streaming + sharded .pt (500K 句/片, 9 片, 总 1.05GB) → O(n) 内存, O(1) 重复实验
- **collate_fn 陷阱**: `torch.tensor(tensor)` 产生未必要的拷贝, 修成直接 `s` 引用
- **greedy_decode bug**: 调用时传了 `beam_size` 关键字但函数签名未接收 → 修成 `**kwargs`
